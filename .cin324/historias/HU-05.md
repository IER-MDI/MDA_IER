## Flujo de interacción
1. El estudiante abre la sección «Tiempo restante» de la aplicación (selector de rol de demostración: Estudiante).
2. El sistema carga del almacén la Carrera demo, su malla de Asignaturas (con la relación «es prerrequisito de») y el avance del Estudiante demo (Asignatura Cursada).
3. El sistema determina las asignaturas pendientes: las que no tienen un registro `resultado = aprobada` en el avance.
4. El sistema calcula la ruta crítica: la cadena más larga de asignaturas pendientes donde cada una exige a la anterior. Una cadena de **N asignaturas sucesivas equivale a N semestres**; sin pendientes, el mínimo es 0.
5. El sistema muestra «Mínimo estimado: N semestres», la lista de asignaturas pendientes y marca como **críticas** las que pertenecen a alguna cadena más larga.
6. El estudiante elige una asignatura pendiente y la acción «Reprobar» o «Postergar», y confirma la simulación.
7. Si la asignatura pertenece a una cadena más larga, el sistema recalcula el mínimo como **N + 1 semestres** e informa un **retraso de 1 semestre**; si no pertenece, mantiene N y el retraso es 0.
8. El sistema muestra el nuevo mínimo y el retraso. La simulación no se guarda; al recargar, vuelve el valor base.

**Variantes:**
- Sin asignaturas pendientes: mínimo 0 semestres y sin opción de simular.
- Varias cadenas de igual longitud: todas sus asignaturas se marcan como críticas.
- «Reprobar» y «Postergar» tienen el mismo efecto: la asignatura no se acredita en ese semestre y corre su cadena un semestre más.
- La simulación se limita a asignaturas pendientes; no aplica sobre asignaturas ya aprobadas.
- No hay sistemas externos ni mensajes a integraciones simuladas.
